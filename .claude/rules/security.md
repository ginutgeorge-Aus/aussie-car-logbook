# Security Checklists

**API routes:**
- File uploads: check `file.size > 50MB` **before** `arrayBuffer()` (OOM DoS); PDF uploads also validate `file.type === "application/pdf"` OR `%PDF` magic header before parsing
- Client FK IDs: `findMany` existence check before insert
- Route param ints: guard `isNaN(id) || id <= 0 || id > 2147483647`
- Bulk-row bodies: cap array length (`z.array(...).max(N)`) — unbounded arrays + per-row writes = DoS
- **Public (unauthenticated) record lookups**: scope by parent — e.g. event success page uses `registration.findFirst({ id, eventId })`, never `findUnique({ id })`. Sequential autoincrement IDs enumerable; unscoped lookup leaks cross-tenant PII

**Server actions:**
- `findUnique` existence check before update/delete
- Child records: verify parent ownership `if (!rec || rec.parentId !== expectedId)`
- Settings upsert: allowlist valid keys
- All Zod strings: add `.max()` bounds
- `accountId` on transaction create/update: validate exists + `isActive` + `account.type === tx.type` (`validateAccount` in `transaction.ts`) — same as petty-cash; prevents FK 500s and INCOME-tx-on-EXPENSE-account P&L corruption

**CSV export**: prefix `=`, `+`, `-`, `@` cells with `'` (formula injection prevention).

# Privacy & Audit

- `/privacy` — public, no auth. Australian Privacy Act.
- `GET /api/people/[id]/export` — ADMIN only. Full person data JSON. Logs `PERSON_EXPORTED`.
- **AUDITOR sees decrypted `ReceiptSend.sentTo` (donor email)** on BOTH the receipt-audit page (`VIEW_RECEIPT_AUDIT_LOG`) and the transaction detail page (`/accounting/transactions/[id]`) — intentional (#396): auditing who a receipt was sent to is core to receipt audit. Not masked. Both pages are gated by `canViewAccounting`.
- Batch receipts skip `emailConsent = false`. Never bulk-email without consent.
- `logAudit(userId, action, resourceType, resourceId?, metadata?, ip?)` — swallows own errors internally. **Callers must NOT add `.catch()`** — redundant and obscures other async errors on same line.
